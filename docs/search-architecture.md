# Search Architecture — Second-Hand Student Marketplace

## Overview

The search system has three layers that operate together:

```
User Query: "cheap scientific calculator for engineering exams under ₹800"
                              │
              ┌───────────────┼────────────────┐
              ▼               ▼                ▼
       Filter Extraction  Keyword Search    Semantic Search
       (lib/search/       (PostgreSQL FTS   (pgvector cosine
        filters.ts)        tsvector/GIN)     similarity)
              │               │                │
              │               └────────┬───────┘
              │                        ▼
              │               Merge + Deduplicate
              │                        │
              └──────────────► Relevance Ranking
                                        │
                               ┌────────┴────────┐
                               │ final_score =    │
                               │  0.55 × semantic │
                               │  0.25 × keyword  │
                               │  0.10 × category │
                               │  0.05 × price    │
                               │  0.05 × recency  │
                               └────────┬────────┘
                                        │
                               Apply hard filters + pagination
                                        │
                                  Final results
```

## Layer 1: Filter Extraction

File: `lib/search/filters.ts`

Parses natural language for structured hints using regex patterns:

| Pattern | Example | Extracted |
|---|---|---|
| `under ₹N`, `below N`, `less than N` | "under ₹800" | `maxPrice: 800` |
| `above N`, `over N` | "above 1000" | `minPrice: 1000` |
| `free` | "free textbooks" | `maxPrice: 0` |
| condition keywords | "used", "brand new", "like new" | `condition: "Good"` |
| category keywords | "calculator", "laptop", "cycle" | `categoryHint: "calculators"` |

These are **soft hints** used in ranking — not enforced as hard filters unless the user also sets explicit filter controls.

## Layer 2: Keyword Search

File: `lib/search/keyword.ts`

Uses PostgreSQL's built-in full-text search:

```sql
-- Using websearch_to_tsquery for safe, natural input
SELECT *, ts_rank_cd(searchable_text, websearch_to_tsquery('english', $1)) AS keyword_rank
FROM listings
WHERE searchable_text @@ websearch_to_tsquery('english', $1)
   OR title ILIKE $2 OR description ILIKE $2
ORDER BY keyword_rank DESC
```

The `searchable_text` column is a `TSVECTOR` maintained by **Trigger T6**:
```
searchable_text = tsvector(title + description + category + condition + location)
```

Fallback: If `websearch_to_tsquery` fails (malformed input), falls back to pure `ILIKE`.

## Layer 3: Semantic Search

File: `lib/search/semantic.ts`

Uses **pgvector** cosine similarity:

```sql
SELECT *, 1.0 - (embedding <=> '[...]'::vector / 2.0) AS semantic_score
FROM listings
WHERE embedding IS NOT NULL
  AND (embedding <=> '[...]'::vector) < threshold
ORDER BY embedding <=> '[...]'::vector
```

The `<=>` operator is pgvector's cosine distance. Distance 0 = identical, 2 = opposite.
We convert to similarity: `similarity = 1 - (distance / 2)` → range [0, 1].

**Embeddings**: Generated by OpenAI `text-embedding-3-small` (1536 dimensions).

**Graceful degradation**: If `OPENAI_API_KEY` is not set or the API call fails, semantic search returns an empty array and the system falls back to keyword-only mode. The marketplace never becomes dependent on the external API.

## Layer 4: Hybrid Ranking

File: `lib/search/ranking.ts`

```
final_score =
    0.55 × semantic_score        (vector cosine similarity)
  + 0.25 × keyword_score         (normalised ts_rank_cd)
  + 0.10 × category_score        (1 if category hint matched, 0 otherwise)
  + 0.05 × price_score           (1 if within price range, penalised if over)
  + 0.05 × recency_score         (exponential decay, 1.0 today → ~0.1 after 60 days)
```

Weight rationale:
- **Semantic (0.55)**: Most important — captures conceptual relevance beyond keywords
- **Keyword (0.25)**: Important — exact and near-exact matches should rank high
- **Category (0.10)**: Useful tiebreaker — narrows scope
- **Price (0.05)**: Soft signal — items within budget preferred but not strictly required
- **Recency (0.05)**: Freshness — newer listings get a slight boost

## Match Labels

Results are labeled for users based on `final_score`:

| Score | Label |
|---|---|
| ≥ 0.65 | Best Match |
| ≥ 0.45 | Great Match |
| ≥ 0.30 | Good Match |
| < 0.30 | (no label) |

Labels only appear when semantic search is active (requires OpenAI API key).

## Search Mode Indicators

The search page displays which mode is active:

- **AI-powered search** (✨): Hybrid mode — both keyword and semantic results combined
- **Keyword search** (⚡): Keyword-only — semantic search unavailable
- No badge: Filter-only browse (no text query entered)
